# ML Homework

Навчальний проєкт з математики, статистики, EDA та машинного навчання.

## Структура

```text
.
|-- data/
|   |-- raw/          # Вхідні дані, які не змінюються
|   `-- processed/    # Результати обробки
|-- notebooks/        # Jupyter notebook-и, згруповані за темами
|-- src/
|   `-- ml_homework/  # Імпортований Python-код проєкту
|-- tests/            # Автоматичні тести Python-коду
|-- Makefile          # Короткі команди для роботи з проєктом
|-- pyproject.toml    # Залежності та налаштування
|-- uv.lock           # Зафіксовані версії пакетів
`-- README.md
```

## Перше налаштування

Відкривайте проєкт з його кореневого каталогу, щоб відносні шляхи `data/...` працювали однаково.

```bash
make setup
```

`make setup` створить `.venv`, встановить залежності та підключить Git hooks. Його достатньо виконати один раз після клонування проєкту.

Шляхи до даних визначені в `ml_homework.paths`. Наприклад: `RAW_DATA_DIR / "medical/file.csv"`.

`src/` містить лише повторно використовуваний Python-код; datasets залишаються в `data/`, а notebook-и — в `notebooks/`. Порожні `__init__.py` не створюються; наявний `src/ml_homework/__init__.py` визначає публічний API пакета.

## Щоденний запуск

```bash
make lab
```

Після `git pull` або зміни `pyproject.toml`:

```bash
make sync
```

## Перевірки якості

```bash
make format  # Виправити Ruff і відформатувати Black
make check   # Запустити Ruff, Black і mypy
```

Вручну запускати перевірки перед комітом чи push не потрібно:

- `git commit` автоматично запускає Ruff і Black для змінених файлів.
- `git push` автоматично запускає `make check`.
- Якщо hook виправив файл, додайте його до Git ще раз і повторіть коміт.
